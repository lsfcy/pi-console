# 界面语言与文案维护

> English summary: Pi Console ships with Simplified Chinese (default) and English. UI strings use the Chinese source text as the catalog key; `t()` translates at render/call time, language changes apply live without restarting Pi, and tests reject missing keys, mismatched placeholders, untranslated source strings, or Chinese text left in the English UI.

Pi Console 默认 **简体中文**，可切换 **English**。语言属于 GUI 偏好，保存在 `projects.json` 的 `preferences.language`；切换立即重新渲染，不重启 Pi、不重建终端、不丢草稿。

## 结构

| 文件 | 内容 |
| --- | --- |
| `src/shared/i18n.ts` | `t()`、`setLanguage()`、`getLanguage()` 与 core 词表；合并各 locale 词表 |
| `src/shared/locales/shell.ts` | 窗口壳层、侧栏、标签、命令面板、控制器通知 |
| `src/shared/locales/sessions.ts` | 会话列表、筛选、监控、格式化 |
| `src/shared/locales/dialogs.ts` | 设置、对话框、确认、项目编辑、统计 |
| `src/shared/locales/main.ts` | 原生菜单、确认、通知、主进程业务错误 |

词表以**中文原文作为 key**：`t('设置')` 在 zh-CN 返回原文，在 en-US 查 `en['设置']`，缺失时回退中文。这样迁移不需要为每条文案另造语义 key，默认中文输出与历史测试完全一致。

## 新增或修改文案

1. 在渲染/调用的位置使用 `t('中文原文')`，不要在模块顶层把 `t()` 结果缓存到常量，否则切换语言不会更新。
2. 在对应 locale 文件补英文 key；英文值不得含中文，占位符必须与中文一致。
3. 动态句子使用**完整模板**，不要把翻译后的片段拼接：
   - 正确：`t('“{name}”已退出（{code}）。', { name, code })`
   - 错误：`t('“') + name + t('”已退出')`
4. 用户内容不翻译：会话标题、首条消息、项目名/路径、模型名、工具输出、终端输出、原始系统异常详情。可以翻译包住它们的固定句子，但变量保持原值。
5. 删除功能时同时删除对应中文 key 与英文词条；不要保留不再引用的词条。

## 渲染器

`WorkspaceController.applyPreferences()` 在每次偏好更新时调用 `setLanguage()`；组件通过 `t()` 在渲染期取文案。状态标签、快捷键标签、格式化函数（日期、货币、相对时间）都在调用/渲染时翻译，不在模块加载时固化。

语言选择在「设置 → 外观 → 界面语言」。设置保存走现有 `setPreferences` IPC，主进程在同一请求内更新语言并重建原生菜单。

## 主进程

`publishPreferences()` 先 `setLanguage()` 再重建菜单；原生菜单、确认框、通知、启动错误和业务错误在产生文案时调用 `t()`。启动错误窗口通过 URL 的 `language` 参数把当前语言传给 renderer，避免错误页固定中文。

Pi bridge 由外部 Pi 进程加载，不能安全 import 共享 i18n。桥接只返回稳定的中文 source 与 `errorVars`，主进程收到后翻译，系统异常保留原始详情。

## 验证

- `tests/i18n.test.cjs`：zh 默认、英文切换、变量插值、回退；四份词表非空、英文无中文、占位符一致；扫描 `src/renderer`、`src/main`、`src/shared`、`src/pi` 的中文字面量，要求都有英文词条。
- `tests/i18n-smoke.cjs`：以 en-US 启动，检查项目页、会话、监控、命令面板、五个设置分区、项目/统计/重命名/确认对话框，以及原生菜单的 `innerText`/attributes 不含中文；测试数据使用英文用户内容，避免把用户文案误判为漏翻。
- `npm run check` 执行静态测试；`npm run test:i18n` 执行 Electron 运行时审计（需要 GUI 环境）。
- CI 的 `npm run check` 会阻止缺失词条、空翻译、占位符不一致与英文残留中文。

## 边界与后续

- 不处理复数/性别/ICU 选择；当前语言只有 zh-CN 与 en-US。
- 中文 key 的优点是迁移成本低、默认输出稳定；缺点是文案改写会导致 key 失效。修改中文原文时必须同步改 key 与英文词条。
- 反向清理（删除不再引用的英文词条）目前靠 code review；如需自动化，可增加“词表 key 必须出现在源码或受控模板中”的反向检查。
